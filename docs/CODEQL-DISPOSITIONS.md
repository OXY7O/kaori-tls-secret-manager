# Reviewed CodeQL findings — intentional operator resource metadata (16 Oct 2026)

## Decision policy

These **31 uniquely identified** CodeQL `py/clear-text-logging-sensitive-data` alerts were cross-checked against [CodeQL SARIF data flows](https://github.com/OXY7O/kaori-tls-secret-manager/actions/workflows/codeql.yml), reviewed source, and the allowlisted operator output policy in [CODE-SCANNING.md](CODE-SCANNING.md). All 31 were **Open** in the live GitHub alert inventory after six original findings were resolved through audited code changes (TLS 1.2, private file creation, exact Gateway API discovery).

The reviewed paths output **Kubernetes Secret resource names, namespace, hostname, SAN, certificate fingerprint, status or metadata** as part of explicit, authorized diagnostics—not a `data.tls.key` value or credential. These fields can still reveal infrastructure topology, so their publication in shared logs or recordings remains a **confidentiality risk**. We preserve this UX for a single accountable operator rather than degrading troubleshooting or silently suppressing the CodeQL rule.

**Disposition:** `won't fix` (intentional operator output with accepted conditional metadata exposure), **NOT fixed**. This means the code will still generate SARIF findings. It does not assert that unrestricted terminal capture is safe or that potential key disclosure via any other path is ruled out. A new or altered data flow must be investigated independently.

## Controlled execution and maintenance

- The one-time workflow `.github/workflows/reviewed-codeql-triage.yml` uses a protected `main` push, a scoped `security-events: write` token, and exact alert **number + CodeQL rule + file + line + state** preflight; abort if any unexpected alert is present.
- Each alert is individually updated with its original classification and justification referencing security backlog [#17](https://github.com/OXY7O/kaori-tls-secret-manager/issues/17); CodeQL queries and uploads remain active.
- **Completed:** [one-time reviewed disposition run](https://github.com/OXY7O/kaori-tls-secret-manager/actions/runs/38821988688) passed strict 31-alert preflight, dismissed all 31 with reason `won't fix` and documented comments, and verified **zero open alerts** immediately afterward. The write-capable workflow, script and temporary test were then removed in the cleanup PR; only read-only inventory remains.
- [Security policy](../SECURITY.md): restrict workstation/terminal session, shell recordings, log forwarding, screenshots, report files, and exported CLI JSON to authorized operations. Do not put private PEM, age identities, tokens, kubeconfigs, or raw production evidence in public artifacts.
- The already dismissed #36 is **not** part of this batch. Six previous alerts disappeared from current SARIF after code hardening; do not count their disappearance as a dismissal.
