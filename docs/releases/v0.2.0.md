# KAORI TLS Management v0.2.0

**Release date:** 16 October 2026  
**Classification:** Semantic Versioning minor source release  
**Distribution:** GitHub archive and SHA-256 checksums

## Improvements

- **Single-operator Update:** same-SAN TLS Secret rotation from the guided wizard with exact target review, verified age-encrypted backup, concurrency safeguards and stored Secret readback.
- **Delete safety:** fail-closed dependency checks include Deployment, StatefulSet, DaemonSet, ReplicaSet, Job and CronJob templates even if no Pod is running, plus Gateway TLS certificateRefs across namespaces.
- **Guarded recovery:** read-only Delete reconciliation and explicit create-only Restore from the original encrypted backup. Only verified complete deletion with pinned cluster/namespace identity is eligible. No overwrite or blind retry.
- **age onboarding:** comprehensive identity-generation, key custody and backup documentation in [AGE-RECOVERY](../AGE-RECOVERY.md), plus wizard help.
- **TLS Doctor:** optional specific LB IP/connect hostname while the original hostname is preserved for SNI and certificate trust checking.
- **Operator acceptance specification:** 15 UAT cases and manual Gherkin scenarios for isolated Kubernetes testing.

## Compatibility and safeguards

Compared with `v0.1.1`, guided menu entries and the `reconcile-delete` / `restore-delete` CLI operations are new. A Delete plan created by earlier versions without a namespace UID **cannot be restored by the new guided workflow**. Expanded safety scans need read access to workload templates and applicable Gateway resources. An incomplete scan is HOLD, never an authorization to force Delete.

## Assurance boundary

Automated checks cover source syntax, synthetic regressions, static analysis and archive integrity without accessing a real cluster. This release **does not attest to completed Kubernetes DEV/UAT, restored backup in a deployed environment, application health, or production readiness**. Before changing any actual cluster, run the [isolated UAT plan](../UAT-PLAN.md), verify recovery key custody and TLS endpoint identity, and follow local change authorization.

## Installation

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/OXY7O/kaori-tls-secret-manager.git
cd kaori-tls-secret-manager
bash scripts/tls-secret-manager.sh doctor
bash scripts/tls-secret-manager.sh wizard --plain
```

Alternatively, download `kaori-tls-management-v0.2.0.tar.gz` and `SHA256SUMS` from the release page. Verify with `sha256sum -c SHA256SUMS` before extracting. The SHA-256 file verifies archive integrity but not publisher authenticity.
