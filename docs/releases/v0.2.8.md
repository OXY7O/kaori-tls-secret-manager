# KAORI TLS Secret Manager v0.2.8

**Release date:** 16 October 2026  
**Classification:** Read-only Inventory API resilience and documentation branding patch

## Fixed: Inventory ALL Kubernetes API timeouts

- Increase Inventory-only Kubernetes GET/LIST request timeout from 20 seconds to **90 seconds** by default; keep user-configurable bounds (20–300 seconds).
- Add read-only LIST pagination (100 objects per page by default, configurable 10–500) and up to **two extra retries**, only on known transient read/API failures.
- Avoid treating TLS Secret API GET failures as `INVALID` certificates. An uncompleted read fails the inventory as `INVENTORY_INCOMPLETE` and no final report is published.
- Include context/namespace/resource/GET-or-LIST/cause in STOP guidance without exposing raw kubectl stderr or Secret payloads. Read-only errors no longer mention rollback/mutation journals.
- Clarify proper `kubectl auth can-i VERB RESOURCE` usage. A `yes` does not rule out Kubernetes API/network timeouts.

The [Inventory troubleshooting guide](../INVENTORY-TROUBLESHOOTING.md) explains settings and read-only diagnosis.

## README and terminal logo identities

The README now uses the **original blue orbital-K artwork**, with corrected text **KAORI / TLS Secret Manager**. The terminal retains the independent **violet four-petal icon** and its full-height neofetch-style metadata panel.

## Compatibility and safeguards

No changes to TLS Secret CREATE/UPDATE/DELETE, renewal, approvals, journal safety, encrypted age backup, or restore behavior. The new retry policy applies **only to Inventory read operations**, never Kubernetes writes. Real-cluster acceptance remains separate from synthetic GitHub Actions checks.
