# KAORI TLS Management v0.1.0

**First official public Semantic Versioning source release** · 15 October 2026  
**Release series:** `0.x` (public SemVer series; interfaces may evolve)  
**Distribution:** Public source archive; deployment authorization belongs to the operator

## Highlights

- Guided TLS Secret Inventory and Expiry Audit, TLS Toolbox/Doctor, HTTPS verification, guarded renewal and recovery evidence.
- Guarded Create/Read/Update/Delete for Kubernetes `kubernetes.io/tls` Secrets with explicit plans, confirm-before-write semantics and fail-closed HOLD/STOP.
- Dependency-aware Delete with Ingress, Pod and Gateway reference checks, Kubernetes UID/resourceVersion preconditions and `age`-encrypted recovery backups.
- Optional independent signed approvals for automation, while the guided workflow supports a single authorized operator.
- Approved KAORI TLS Management PNG wordmark with terminal-aware inline and plain-text fallbacks.
- Complete operator documentation, community contribution policies and offline regression tests.

This release promotes the source already made available as `v0.1.0-rc.1`, plus documentation, SemVer publishing and release automation updates. No live Kubernetes mutation logic was changed for this version.

## Download and verify

The uploaded `kaori-tls-management-v0.1.0.tar.gz` is a **source code archive**, not an executable installer. Download it together with `SHA256SUMS` from the [v0.1.0 release assets](https://github.com/OXY7O/kaori-tls-secret-manager/releases/tag/v0.1.0) into the same local directory.

```bash
sha256sum -c SHA256SUMS
tar -xzf kaori-tls-management-v0.1.0.tar.gz
cd kaori-tls-management-v0.1.0
bash scripts/tls-secret-manager.sh doctor
bash scripts/tls-secret-manager.sh wizard --plain
```

Or retrieve the tagged source from GitHub:

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/OXY7O/kaori-tls-secret-manager.git
cd kaori-tls-secret-manager
bash scripts/tls-secret-manager.sh doctor
```

`SHA256SUMS` verifies downloaded content integrity, **not cryptographic signing by the publisher**.

## Requirements and tested scope

- Linux / WSL2, Bash, Python 3.10+ (Python 3.12 tested in CI), OpenSSL and `age`.
- `kubectl` plus an **explicitly authorized** Kubernetes context only for cluster reads or permitted live operations.
- The release pipeline runs compilation, synthetic offline regression and CLI entrypoint checks without Kubernetes credentials.

**Operational assurance:** This release is validated by source-level CI. It does not include an independent infrastructure security certification or universal Kubernetes compatibility guarantee. Administrators must authorize deployments, verify live RBAC and dependency checks, practice encrypted recovery, and confirm endpoint trust in their environment. No vendor SLA is supplied.
