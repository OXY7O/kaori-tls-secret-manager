# KAORI TLS Secret Manager v0.2.9

**Release date:** 19 October 2026  
**Classification:** Guarded interactive multi-target TLS Secret renewal workflow

## Single-operator batch renewal

One authorized operator can now renew **multiple READY Kubernetes TLS Secrets** whose HTTPS endpoints are **Secret-bound**, without creating a separate approver JSON, OpenSSL detached signature or installed approver public PEM.

Use the regular interactive wizard:

```bash
bash scripts/tls-secret-manager.sh wizard
```

Select **Renew TLS Secrets**, choose several TLS Secret targets, then complete discovery, target validation, certificate/key selection and a read-only renewal plan. At Step 7 the wizard prints each READY `namespace/secret` identity and asks for the exact phrase `RENEW N TLS SECRETS`, followed by `AUTHORIZED` and the exact Plan ID. The wizard collects the age recovery identity for the encrypted pre-write backup.

The renewal backend requires a live TTY plus those exact batch/plan confirmations. Its journal records `authorization_method=SINGLE_OPERATOR_BATCH`. No unattended multi-target write is silently enabled.

## Safeguards retained

- Only READY entries are eligible; HOLD and SKIPPED are unchanged.
- Exact Kubernetes context, cluster UID, Secret UID/resourceVersion, source certificate SAN/fingerprint and reviewed endpoint mapping stay pinned to the plan.
- All READY targets receive an encrypted backup before any write. For each target, the updated Secret is checked and the associated HTTPS endpoint must verify before continuing to the next READY Secret.
- A timeout or failed wave stops later writes and creates reconciliation evidence; do not blindly retry an uncertain mutation.
- **External TLS termination still requires a separate approver's signed authorization**, even for one target.
- Non-interactive multi-target renewal still requires independently signed approval. Interactive operator mode and signed evidence cannot be mixed.
- The typed confirmations do not grant Kubernetes RBAC or replace the organization's own change-control requirements.

Read the [Operator Guide](../OPERATOR-GUIDE.md) and [Scope and Authorization](../SCOPE-AND-AUTHORIZATION.md) before performing a production change.

## Quality and acceptance

Synthetic regression coverage includes TTY enforcement, batch count/Plan ID mismatch, external TLS rejection, signed fallback, and READY/HOLD target filtering. Passing GitHub Actions is not evidence of a completed Kubernetes UAT or verified HTTPS deployment.
