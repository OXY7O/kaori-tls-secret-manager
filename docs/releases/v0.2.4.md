# KAORI TLS Secret Manager v0.2.4

**Release date:** 16 October 2026  
**Classification:** Scope, nomenclature, help/approval clarity and wordmark patch  
**Distribution:** GitHub source archive and SHA-256 checksums

## Canonical product purpose

**KAORI TLS Secret Manager** is a terminal utility for inspecting and managing **Kubernetes TLS Secrets** (`type: kubernetes.io/tls`). The tagline is **Safer Kubernetes TLS Secret management**. It is *not* a certificate authority, certificate issuer, ACME client, replacement for cert-manager or general-purpose certificate manager.

The distributed wordmark now says **KAORI TLS Secret Manager**, matching the README and CLI guidance. This does not change the separate approved purple icon that appears in the terminal.

## Clarified authorization

The former misleading renewal warning that combined **“Use only in authorized DEV/UAT”** with **“Approval is required before a write”** is replaced by precise, flow-specific requirements:

- Inventory, diagnosis and planning are read-only and require only applicable read RBAC; **no mutation approval**.
- Guided single-operator Create/Update/Delete requires a reviewed plan and explicit action/target confirmation; Delete also requires external consumer attestation and verified age recovery backup.
- Guided renewal of one READY TLS Secret requires operator **AUTHORIZED** and exact Plan ID; renewal of multiple READY Secrets or external TLS termination **also** requires independently signed approval.
- Advanced non-interactive enterprise writes retain their independently signed approval requirements.
- DEV/UAT should be used for testing before production; production is not blocked by the code, but needs its own Kubernetes authorization, UAT and organizational approval.

The [Scope and authorization guide](../SCOPE-AND-AUTHORIZATION.md) and active documentation use these definitions consistently. Earlier immutable release notes remain historical snapshots.

## Compatibility / release evidence

This is a terminology and public logo update. No backend Secret mutation, Kubernetes authorization enforcement, age encryption, backup or restore safety logic was modified. CI uses synthetic checks and is **not** proof of production Kubernetes UAT.

## Install

```bash
git clone --branch v0.2.4 --depth 1 https://github.com/OXY7O/kaori-tls-secret-manager.git
cd kaori-tls-secret-manager
bash scripts/tls-secret-manager.sh doctor
bash scripts/tls-secret-manager.sh wizard
```

Use `wizard --plain` for accessible text-only menus. Verify published archive checksums before extraction.
