# KAORI TLS Secret Manager v0.2.5

**Release date:** 16 October 2026  
**Classification:** Product naming / source artifact packaging consistency patch

## Canonical identity and scope

The published title is **KAORI TLS Secret Manager v0.2.5**. The tool is for managing **Kubernetes TLS Secrets** (`type: kubernetes.io/tls`), not general-purpose certificate issuance or CA operations.

The corrected purple icon and README wordmark use **KAORI TLS Secret Manager**. The current CLI warnings, operator documentation and exact authorization conditions introduced in v0.2.4 remain unchanged.

## Packaging correction

Starting in v0.2.5, the downloadable source archive is:

- `kaori-tls-secret-manager-v0.2.5.tar.gz`
- `SHA256SUMS` (checksum for the archive above)

The extracted directory is `kaori-tls-secret-manager-v0.2.5/`. Previous already published releases use their original legacy archive names and remain immutable. Any scripted download should use the new basename for this version and later.

## Authorization and operational scope

Read-only inspection and planning require Kubernetes read RBAC, not write approval. Guided Create/Update/Delete uses deliberate one-person target/action confirmations. One-target guided renewal requires `AUTHORIZED` and exact Plan ID. Multi-target or externally terminated TLS renewal additionally requires a separately signed approver record. These rules are documented in [Scope and authorization](../SCOPE-AND-AUTHORIZATION.md).

No Kubernetes Secret write implementation, age backup/restore, dependency scan, or security bypass behavior changed in this naming-only patch. Offline GitHub Actions do not certify UAT in any real Kubernetes environment.

## Install

```bash
git clone --branch v0.2.5 --depth 1 https://github.com/OXY7O/kaori-tls-secret-manager.git
cd kaori-tls-secret-manager
bash scripts/tls-secret-manager.sh doctor
bash scripts/tls-secret-manager.sh wizard
```

To install from GitHub Release assets, verify `sha256sum -c SHA256SUMS` after downloading the source archive and checksum.
